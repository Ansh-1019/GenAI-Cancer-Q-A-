# GenAI Cancer Q&A RAG System (Gemini + Chroma)

This project demonstrates a Retrieval-Augmented Generation (RAG) system using LangChain components. It connects to a local Chroma vector database, retrieves relevant context from clinical databases and documents, and uses Google's Gemini LLM to generate evidence-based answers.

## Reorganized Project Structure

The project has been cleaned up and reorganized into the following clean layout:

```text
├── backend/
│   ├── ingestion/             # Ingestion scripts to populate ChromaDB
│   │   ├── icd10_ingest.py        # Fetches and indexes ICD-10 cancer codes
│   │   ├── pubmed_ema_ingest.py   # Indexes PubMed abstracts & EMA JSON datasets
│   │   ├── pdf_ingest.py          # Chunks and indexes guideline PDFs
│   │   └── openfda_ingest.py      # Fetches and indexes FDA drug adverse events
│   ├── .env                   # Environment variables (GOOGLE_API_KEY)
│   ├── api.py                 # FastAPI server providing the RAG endpoints and built-in UI
│   ├── demo.py                # Command-line query runner
│   ├── rag_query.py           # Core RAG retrieval and generation logic
│   └── verify_chroma.py       # DB connection and document count verification utility
├── data/                      # Consolidated raw datasets
│   ├── guideline_pdfs/        # EAU & ESMO cancer guideline PDFs
│   └── raw_json/              # PubMed & EMA raw JSON files
├── frontend/                  # React web frontend interface
├── chroma_knowledge_base/     # Persistent local Chroma vector database index
├── venv/                      # Python virtual environment
├── .gitignore                 # Excludes environments and database indices from git
├── README.md                  # This file
└── rag_output.txt             # Query output generated by the CLI demo
```

## Prerequisites

- **Python:** Ensure you have Python installed.
- **Environment Variables:** You must have a `.env` file in the `backend/` directory containing your Google API key:
  ```env
  GOOGLE_API_KEY=your_actual_api_key_here
  ```
- **Vector Database:** The persistent database is pre-populated in the root `./chroma_knowledge_base` folder.

## Setup and Installation

1. Navigate to the project root directory.
2. Activate the virtual environment (recommended):
   ```bash
   venv\Scripts\activate
   ```
3. Install the required dependencies:
   ```bash
   pip install python-dotenv langchain-community langchain-google-genai sentence-transformers chromadb fastapi uvicorn pydantic langchain-classic
   ```

## Usage

### 1. Verify Database
To verify that the database exists and has documents loaded, run the connection verification utility:
```bash
python backend/verify_chroma.py
```

### 2. Run CLI Demo
To run a query from the command line and output the generated answer along with retrieved document snippets to a file, run:
```bash
python backend/demo.py
```
This will generate/overwrite `rag_output.txt` at the project root.

### 3. Launch Web API and Built-in UI (FastAPI)
To launch the FastAPI server (which serves the API and the built-in simple chat client):
```bash
uvicorn backend.api:app --reload
```
Once running, you can visit `http://127.0.0.1:8000` in your browser to chat with the assistant.

### 4. Run React Frontend
The React frontend lives in the `frontend` folder and communicates with the FastAPI backend. To start it:
```bash
cd frontend
npm install
npm start
```
This launches the interactive React UI at `http://localhost:3000`.

## Re-Running Ingestion (Optional)
If you ever need to rebuild or add new data to the vector database, run the scripts in `backend/ingestion/` in the following logical order from the root folder:
1. `python backend/ingestion/icd10_ingest.py` (Creates/resets DB and indexes ICD-10 codes)
2. `python backend/ingestion/pubmed_ema_ingest.py` (Indexes PubMed abstracts & EMA documents)
3. `python backend/ingestion/pdf_ingest.py` (Indexes guideline PDFs)
4. `python backend/ingestion/openfda_ingest.py` (Indexes openFDA Adverse Event summaries)
